04 · Approach

How I build

Saying it works is not enough; show how it was verified.

  1. Architecture

    I keep logic apart from shells like Android, the network and the disk: pure classes, hand-wired dependency injection, one network exit. That is how RideDeck's GPS filter and crash detection, and Aile Cüzdanı's service layer, are tested without a device.

  2. Testing

    Unit tests, type checks and lint run on every change. Aile Cüzdanı also has HTTP-level integration checks against a real PocketBase instance. RideDeck's CI runs tests, lint and an R8-minified release build. I do not describe something as field-tested when it is not.

  3. Privacy

    Data that does not need to be collected is not collected: RideDeck has no account or server, EXIF Cleaner and Sohbet Özeti are locked off the network by a content security policy. In Aile Cüzdanı personal data is kept only so the product can work.

  4. Security

    Authorization is decided on the server, not the client: access rules, role checks, rate limiting. Secrets and private source never enter public repositories; tests never write to the live database.

  5. Deployment

    Changes move in small commits. Mobile builds ship signed on GitHub Releases; this site is served from my own server with Caddy. Database changes are append-only migration files, and every step that touches a live system has a way back.
